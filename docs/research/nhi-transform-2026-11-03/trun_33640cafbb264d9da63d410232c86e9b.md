# Offline GitHub-to-AWS Analysis That Preserves Evidence and Uncertainty

## Executive Summary

**Assessment date: 2026-11-03.** The recommendations below are proposed engineering designs, not measured accuracy or validated novelty claims.

- **One Shared Witness**: AWS distinguishes exact `StringEquals` from wildcard `StringLike` matching. Independently satisfiable predicates can still have an empty intersection -> solve the complete condition over one correlated context. [6]
- **Deny-Aware Uncertainty**: One applicable explicit Deny defeats an Allow; resource-policy exceptions also prevent a universal intersection model -> distinguish blocked, possible, supported-under-assumptions, and unknown reachability. [1]
- **Surviving Credentials**: Web-identity sessions default to **3,600 seconds**, while callers can request up to the role's configured maximum, potentially **12 hours** -> do not treat an action's requested duration as the attacker's ceiling. [2]
- **Temporal Containment**: AWS revocation uses an issuance-time cutoff, while later sessions can escape that cutoff -> close renewal paths and retain existing sessions during replay. [10]
- **Scope-Matched Validation**: AWS's simulator and open implementations are useful comparators, not interchangeable end-to-end oracles -> compare only overlapping semantics and report unsupported cases separately.
- **Local-First Delivery**: Keep parsing, solving, evidence storage, and reporting offline. Python remains a reasonable integration layer; adopt other components only behind bounded, reproducible interfaces.

## 1. Shared Witnesses Prevent Symbolic OIDC False Positives

Represent an admissible workflow context as a relation, not independent sets of subjects and refs:

`C = (repository, event, ref, environment, workflow identity, audience, subject, key presence)`.

For a statement with predicates `P1 ... Pn`, test:

`exists c: WorkflowConstraints(c) AND P1(c) AND ... AND Pn(c)`.

The quantifier must surround the entire conjunction. Checking `exists c: Pi(c)` separately permits incompatible witnesses. AWS's distinction between literal equality and wildcard matching is essential: `*` in `StringEquals` is not an AWS glob. [6]

**Regression case.** Suppose the subject domain contains only a `main` subject and a `release` subject. `StringEquals(sub, main)` and `StringLike(sub, release*)` are individually satisfiable but jointly unsatisfiable. A matcher that unions their witnesses invents a role-assumption path. The correct explanation identifies the conflicting predicates rather than merely displaying a red edge.

Preserve GitHub's subject-construction alternatives and correlations. Environment, pull-request, branch, and tag subjects are not interchangeable; customized subjects require their own template evidence. GitHub's OIDC reference is the authoritative schema source. Do not assume that every JWT claim, including `ref`, is independently available as an AWS condition key: maintain a separate AWS key-mapping layer. Correlations can constrain the internal model even where AWS cannot test the claim directly.

There is also an upstream execution boundary. A fork `pull_request` normally receives a read-only token and no other repository secrets, whereas executing fork-controlled content in a privileged `pull_request_target` context can expose credentials. Merely observing a workflow trigger therefore does not establish attacker execution or credential access. [24]

**Decision:** issue a concrete shared witness for satisfiable conditions, a contradiction explanation for unsatisfiable ones, and `unknown` for unsupported expressions or claim templates.

## 2. Missing Evidence Can Both Add and Remove Reachability

Evaluate two different requests: the STS issuance request and each subsequent AWS operation. At each stage, an applicable explicit Deny overrides Allow. Model trust, identity, boundary, session, resource, KMS key, SCP, and RCP policies according to their applicability, not as one undifferentiated list. [1]

A blanket intersection is incorrect. Within an account, direct grants to some user or session principals can bypass implicit denials in identity, boundary, or session policies; role-ARN grants behave differently. Trust and KMS key policies also require explicit authorization in relevant cases. [1]

**Failure case.** An exported identity policy permits an operation, but the export omits a boundary containing a matching Deny. Calling the observed graph a universal lower bound is wrong: adding evidence removes that path. Conversely, an omitted resource grant can add a path.

Distinguish three states for a runtime key: **known present**, **known absent**, and **unobserved**. AWS's missing-key semantics vary: ordinary positive comparisons generally fail, negated comparisons can succeed, and `IfExists` changes evaluation again. Unobserved evidence is not a known-absent request key. [6]

Use may/must reasoning only relative to a declared, consistent set of model completions. A possible Deny should weaken a positive conclusion, not become a definite block. A missing grant source should preserve uncertainty, not silently become an empty policy.

**Decision:** attach assumptions and missing-source obligations to every positive or negative conclusion; reserve unconditional language for genuinely closed scopes.

## 3. Replay Containment Against Credential Versions, Not Just Edges

An action's requested session duration describes its configured invocation, not necessarily what an attacker controlling a valid web-identity token can request. `AssumeRoleWithWebIdentity` accepts durations from **900 seconds** to the role maximum; excessive requests fail. [2]

**Containment case.** An analyst removes a permissive trust statement and shortens the workflow's requested duration. This prevents some future issuance but does not establish that previously issued credentials have expired. AWS evaluates temporary-credential permissions on subsequent requests; policy changes can affect existing sessions, and propagation can take a few minutes. [12]

Represent each session with its issuer, issuance-time interval, expiration interval, credential version, and revocation coverage. An unknown issuance time remains unknown. Trust changes remove future minting opportunities; they must not delete historical session nodes from replay.

AWS's `AWSRevokeOlderSessions` policy denies permissions based on `aws:TokenIssueTime`. Sessions created after the cutoff are not covered. The console procedure includes approximately **30 seconds** of future coverage to account for propagation, but that is not a universal containment deadline. [10]

**Rotation case.** Credential A can read replacement credential B. Rotating B while A remains usable re-exposes B. Build dependencies between credential *versions*: exposure access, replacement publication, old-version deactivation, session revocation, and verification. Unrotated roots remain capable of recreating descendants unless their renewal access is closed.

Collapse cyclic dependencies into strongly connected components, then schedule the component DAG. An SCC is a coordinated isolation-and-rotation batch, not an assertion that AWS provides atomic multi-credential rotation. Revoke surviving sessions and reopen access only after the batch's exposure paths are closed.

**Decision:** compare containment plans by residual reach over time, operational disruption, and unresolved survival assumptions, not simply deleted-edge counts.

## 4. Combine Formal Methods Instead of Selecting One Solver

Zelkova already translates policies and properties into SMT, using strings, regular expressions, bit vectors, and integer comparisons. This establishes substantial prior art; symbolic policy reasoning itself is not a defensible novelty claim. [9]

| Approach | Best role in this system | Complexity and principal risk |
|---|---|---|
| Regular-language automata | Exact literal/glob domains, intersections, complements, witness strings | Fixed DFA products are manageable; determinization and multiple intersections can grow exponentially. Alphabet and glob-dialect mistakes change meaning. |
| Abstract interpretation / may-must | Explicit uncertainty and scalable fixpoints | Precision depends on the abstract domain; convergence techniques can lose correlations. Bounds apply to the declared model, not automatically to AWS reality. |
| SMT | Shared witnesses, claim relationships, numeric/time constraints | Expressive combinations and quantified encodings can time out. Return `unknown`, never convert timeout into UNSAT. |
| Datalog / graphs | Provenance-bearing derivations, reachability, SCCs | Graph reachability and SCCs are linear in explicit graph size; rule joins and context expansion can dominate. Boolean edges alone lose condition compatibility. |
| Bounded MILP/MaxSAT/search | Budgeted containment schedules and rotation batches | Combinatorial optimization can be expensive; horizon and candidate-action restrictions limit conclusions. Report feasible bounds and optimality gaps. |

These approaches address different bottlenecks. Use automata for the supported string fragment, relational constraints for context compatibility, and graphs for explanations; invoke optimization only after fixing the transition semantics.

Relevant foundations include Cousot and Cousot's **1977** abstract-interpretation paper; Ou, Govindavajhala, and Appel's **2005** *MulVAL*; and Wang, Noel, and Jajodia's *Minimum-cost network hardening using attack graphs*, published **28 November 2006**. Quacky's *Quantifying permissiveness of access control policies* is relevant to bounded permissiveness measurement, not evidence that an offline scanner reproduces complete runtime authorization.

**Decision:** preserve Python orchestration. `automata-lib`, Quacky, and `iam-simulate` are implementation candidates or comparators, not drop-in proofs of AWS equivalence.

## 6. Falsifiable Tests Must Separate Semantics From Relationships

Build three independent evaluation layers:

1. **Semantic regression and mutation.** Include conflicting shared witnesses, literal `*`, OR-valued alternatives, missing/unknown keys, negated operators, explicit and possible Denies, principal-type exceptions, session cutoffs, unknown sessions, re-exposure cycles, and unsupported syntax. Mutations should deliberately change expected outcomes; not every mutation should be detected as a vulnerability.
2. **Independent oracles.** Exhaustively enumerate deliberately small alphabets, contexts, and time horizons using a separately implemented interpreter. Differentially compare automata, SMT, and `iam-simulate` only on their supported intersection. Keep independently obtained vendor results as versioned fixtures, never hidden live dependencies.
3. **Blinded relationship labels.** Have independent reviewers label attacker-control, credential exposure, trust compatibility, authorization, and survival separately without seeing tool outputs. Record evidence spans, disagreements, adjudication, and `insufficient evidence`. Separate repositories used for development from held-out evaluation.

Use repository-cluster bootstrap intervals rather than treating correlated edges as independent observations. Publish precision, recall, abstention, unsupported-feature rate, and label agreement by relationship type.

Benchmark sparse chains, dense graphs, wildcard-heavy conditions, large SCCs, malformed/alias-heavy YAML, parser failures, report generation, and peak memory separately. Record cold/warm time, solver budgets, state counts, graph size, output bytes, and deterministic replay hashes.

**Decision:** compare tools by task: linting, concrete simulation, symbolic policy comparison, workflow execution exposure, or temporal containment. A broader output list is not evidence of higher accuracy.

## 7. Coverage-Aware Diffs and Accessible Offline Evidence

**Diff failure case.** A finding disappears because its YAML file stops parsing. Reporting it as resolved rewards loss of visibility. Maintain a per-source ledger containing discovered files, hashes, parser/version, supported constructs, exclusions, and errors. Report `resolved` only when the relevant observation obligation remains covered; otherwise use `not observed`, `unsupported`, or `scope changed`.

Every relationship should retain source location, content hash, extraction rule, normalized predicate, assumptions, and witness or contradiction. A replay bundle should include supplied runtime context, claim templates, policy inventory, time assumptions, tool versions, and analysis limits. Stable identifiers, canonical ordering, normalized paths, and separated volatile metadata make equivalent runs reproducible.

For analysts, provide a path narrative and synchronized table alongside the graph: attacker control -> token context -> trust -> session -> operation -> survival -> containment. Include keyboard navigation, visible focus, non-color status cues, and textual alternatives. WCAG 2.2 is dated **5 October 2023**; do not present its AAA animation criterion as an AA requirement.

Generate a self-contained HTML file with escaped text, no remote assets, hash-authorized scripts/styles, and restrictive CSP, including `default-src 'none'`, `connect-src 'none'`, `object-src 'none'`, and `base-uri 'none'`. CSP Level 3's dated **16 September 2026** draft also matters because some directives, notably `frame-ancestors`, are not enforceable through a meta policy. CSP supplements safe rendering; it does not replace it.

**Decision:** default to no automatic motion, honor reduced-motion preferences, and label print/share exports as either filtered views or complete evidence bundles, with omitted counts and uncertainty intact.

## 8. Five Feasible Innovations With Acceptance Gates

All benefits below are hypotheses to test, not achieved results.

| Priority and proposed innovation | Expected measurable benefit | Alternative, dependency, and acceptance criterion |
|---|---|---|
| **1. Shared-witness condition certificates** | Fewer incompatible-context false positives | Versus independent glob checks; needs claim mapping and supported semantics. Accept when exhaustive finite-domain oracles agree on every supported regression and each positive witness rechecks independently. |
| **2. Deny-aware uncertainty plus coverage-safe diffs** | Fewer unsupported positives and false resolutions | Versus binary findings; needs source ledgers and explicit unknown states. Accept when removing a restriction source weakens certainty and parser-loss mutations never produce `resolved`. |
| **3. Versioned temporal replay with SCC rotation batches** | Lower residual credential reach than edge deletion | Versus static cut sets; needs issuance intervals and exposure dependencies. Accept when replay retains all unexpired/unknown sessions and exhaustive small cases detect every planted re-exposure cycle. |
| **4. Bounded containment optimization with certificates** | Better containment per declared disruption budget | Versus documented greedy ordering; needs validated replay. Accept only if small-instance optima match enumeration and larger runs expose feasibility, horizon, and optimality gap. |
| **5. Deterministic, accessible evidence capsules** | Faster analyst explanation and reliable offline handoff | Versus graph-only HTML; needs canonical serialization, safe rendering, and text alternatives. Accept when replay is byte-stable, network attempts are absent in browser tests, and blinded users complete explanation tasks without graph interaction. |

These are highest-value integration opportunities, not claims that their constituent algorithms are new. Set performance and analyst-task thresholds before the held-out evaluation.

## Synthesis

Automata offer precise string-language reasoning but can explode in size; SMT preserves richer correlations but introduces timeout risk. Abstract interpretation controls uncertainty and scale at a precision cost. Datalog exposes derivations but needs relational guards; optimization chooses actions but is only as sound as its temporal model.

The important tension is **precision versus closure**: a perfect solver over incomplete policy exports still cannot establish complete AWS reachability. Likewise, removing a minting edge does not remove already-issued credentials, and rotating a secret does not close its re-exposure path.

The strongest feasible design is therefore a bounded, provenance-bearing local analyzer: exact where its semantics and evidence are closed, explicit where they are not, and conservative about credential survival. Whether this combination yields novel research or superior practical outcomes remains an empirical question.
