# Making Offline Cloud Reachability Claims Falsifiable

## Executive Summary

**Assessment: 2026-11-03.** The strongest differentiation is a falsifiable combination of established methods, not a new satisfiability algorithm or a demonstrated accuracy advantage.

- **Versioned OIDC Subjects**: GitHub documents an immutable-subject rollout after **2026-07-15** -> a legacy-only subject grammar is insufficient. [12]
- **One Shared Witness**: AWS combines condition operators with AND -> solve one complete request, not independently compatible predicates. [33]
- **Directional Uncertainty**: Missing grants and missing restrictions have opposite effects -> publish completion-relative may/must bounds, not a universal lower bound.
- **Surviving Authority**: Web-identity callers can request up to the role maximum, potentially **12 hours** -> configured workflow duration is not an attacker ceiling. [4]
- **Cutoff Is Not Convergence**: Revocation selects sessions by issuance time; policy updates can take minutes -> track coverage and activation separately. [6][24]
- **Evidence Before Superiority**: Existing policy solvers, attack-graph hardening and proof-carrying authentication invalidate broad novelty claims -> test the narrower combination. [16][11][30]


## 1. Make OIDC Witnesses Schema-Aware

**A material update to the previous analysis:** GitHub now documents `repo:OWNER@OWNER-ID/REPO@REPO-ID:ref:refs/heads/BRANCH`. Repositories created after **2026-07-15** use this immutable format; older repositories retain the previous format unless opted in, while subsequent renames/transfers also move to it. GitHub Enterprise Server is excluded from this rollout. [12]

For the documented subject contexts, environment takes precedence over pull-request and branch/tag forms. Custom templates replace the whole subject; immutable-format repository segments retain their IDs even under customization. Organization-template adoption is itself opt-in. Thus repository names, creation dates, template settings and deployment context are analytical inputs, not interchangeable strings. [12]

**Constructed regression case:** a symbolic subject domain contains both `repo:o/r:ref:refs/heads/main` and `repo:o/r:environment:prod`. A `StringEquals` predicate requires the first; a `StringLike` predicate requires `repo:o/r:environment:*`. Each predicate separately has a witness, but their conjunction has none. The correct query is:

`exists c: IssuerDomain(c) AND WorkflowEvidence(c) AND WholeCondition(c)`

The same context `c` must satisfy every conjunct. AWS uses AND across operators/keys, OR across positive values, and NOR across values under negated matching. `StringEquals` treats `*` literally; `StringLike` recognizes `*` and `?`. Do not substitute Python `fnmatch` without removing its additional pattern language. [33][13]

Keep `present`, `absent` and `unobserved` distinct. Ordinary positive comparisons fail on absent keys, negated comparisons can succeed, `IfExists` changes absence behavior, and `ForAllValues` can be vacuously true without `Null:false`. Unobserved is an epistemic state, not AWS's absent-key value. [13]

GitHub states that AWS does not support arbitrary custom OIDC claims. Correlate `ref` internally with the subject schema and workflow evidence; do not manufacture a usable IAM `:ref` condition key. Unknown templates require widening or an indeterminate result, not a legacy-format fallback. [27]

**Decision:** make issuer-schema selection part of the witness certificate.


## 2. Bound Coherent Worlds, Not Independently Labeled Edges

Let `W(E)` contain complete, coherent policy/context/credential worlds compatible with evidence `E`, within an explicitly declared inventory and time horizon. Define:

`May(E) = union Reach(w)` and `Must(E) = intersection Reach(w)`, for `w in W(E)`.

These are proposed model semantics, grounded in the sound-approximation discipline of Patrick and Radhia Cousot's **Abstract Interpretation** framework. An empty `W(E)` means inconsistent evidence, not vacuous proof of universal reachability. [25]

Omitted grants can add paths; omitted restrictions can remove them; truncation can do both. Missing runtime keys differ again from an incomplete policy inventory. A universal claim that observed reachability underapproximates actual access is therefore unjustified. Report the uncertainty direction, source and assumptions separately.

**AWS case:** a same-account resource policy grants directly to an assumed-role session, while a boundary lacks the action. A universal identity/boundary/session intersection incorrectly rejects access: direct session grants can bypass those *implicit* denials. Grants to a role ARN remain boundary/session-limited, and wildcard `Principal` plus `aws:PrincipalArn` has another documented exception. Applicable explicit Deny still wins. [17]

Consequently, trust, identity, boundary, session, resource, key and organization policies need typed evaluators, including principal form, account relationship and service exceptions. SCPs/RCPs are guardrails, not independent grants. KMS additionally evaluates key policies and grants; cross-account IAM delegation depends on permission from the key-owning account. [17][1]

A Deny statement's presence is not proof of applicability. A definitely applicable Deny excludes the corresponding request worlds; a possibly applicable Deny prevents an unconditional supported-access claim. Solve Allow and Deny under the same context: separately satisfiable grants and restrictions cannot be combined into a fictitious world.

**Decision:** reserve "must" for the declared completion model; distinguish snapshot-relative conclusions from claims about an incompletely observed AWS account.


## 3. Replay Possession, Authority And Credential Versions

`AssumeRoleWithWebIdentity` defaults to **3,600 seconds**, permits requests from **900 seconds** to the role maximum, and accepts optional session policies. The role maximum can reach **43,200 seconds**. The AWS credentials action also documents a one-hour default and optional session policies. If an attacker can call STS directly with an accepted token, neither that action's shorter request nor its optional restrictive policy necessarily binds the attacker. Ordinary role chaining has a separate **one-hour** limit. [4][34][9]

An already-issued session is a separate state object from its minting edge. Permissions are reevaluated on each request, so retain the session's possession/expiry record while recomputing its current authority. Closing trust is not equivalent to applying a session-authorization Deny. AWS's revocation mechanism uses an issuance-time cutoff and does not cover later sessions. [24][6]

**Constructed containment case:** session `S0` can read credential `K0`, and another path can mint `S1`. Rotating the stored credential without containing `S0` merely exposes replacement `K1`.

| Replay event | State that must survive | Incorrect conclusion to reject |
|---|---|---|
| Close OIDC trust | Previously obtained sessions and other authenticating roots | All attacker access disappeared |
| Replace `K0` with `K1` | Readers capable of obtaining `K1` | Rotation alone contained the incident |
| Apply cutoff `c` | Sessions issued at/after `c`; uncovered alternative roots | Every session is covered |
| Submit a Deny update | Pending/unknown activation state | Submission proves effective denial |

The table separates possession, issuance coverage and authorization activation. AWS explicitly warns that permission updates might take a few minutes; offline evidence cannot establish convergence by itself. [24]

Represent each credential generation separately and each reissue route as an alternative derivation. If authority A can read replacement B, contain A before treating B's rotation as durable. Cyclic dependencies require isolation plus a coordinated rotation batch, not an allegedly safe arbitrary ordering. An SCC identifies a cycle; it does not prove that external reissue paths were cut.

**Decision:** a containment result must state its horizon, surviving roots, unknown sessions, re-exposure paths and activation assumptions.


## 4. Choose Algorithms By Their Correctness Obligations

Backes et al.'s **Semantic-based Automated Reasoning for AWS Access Policies using SMT** already encodes policy semantics over shared request contexts. Its PSPACE-completeness result concerns wildcard-string policy constraints; timeout/unsupported cases return `unknown`. This is substantial prior art, but not a ready-made GitHub-to-AWS temporal model. [16]

Eiers et al.'s **Quantifying Permissiveness of Access Control Policies** adds model counting. Its experiments bound strings to **100 characters** over a **256-character alphabet**. Exactness inside that universe does not establish unbounded exclusion; omitting service-type constraints can overapproximate permissiveness. [22]

| Method | Obligation and failure mode | Cost and appropriate baseline |
|---|---|---|
| Glob automata | Preserve literal/operator semantics, presence and correlated schema; bounded exhaustion is not global UNSAT | On-the-fly product traversal; product states can multiply across predicates |
| Abstract interpretation | Sound concretization and transfer functions; distinguish lost precision from exclusion | Worklist fixpoint over finite-height domains; widening trades precision for termination |
| SMT | Encode the complete supported semantics; timeout is unknown | Expressive independent development oracle, not required runtime dependency |
| Datalog / hypergraph | Preserve conjunctive prerequisites, alternative derivations and coherent context | Fixed-rule finite-domain evaluation can be polynomial, but grounding and path output can dominate |
| SCC / cuts / bounded optimization | Retain credential versions and temporal effects; do not equate a static cut with containment | SCC/reach traversal is `O(V+E)`; general action-set planning admits combinatorial explosion |

These costs describe the proposed representations, not measured performance. MulVAL demonstrates Datalog attack analysis; Wang, Noel and Jajodia demonstrate minimum-cost hardening over adjustable conditions. Neither establishes correctness for the proposed session replay. [18][11]

**Decision:** implement small Python glob automata, presence-aware abstract states, typed policy evaluators and a finite transition worklist first. Cap products, grounding and time states explicitly; return resource-limit uncertainty rather than silent exclusion.


## 5. Five Improvements With Explicit Release Gates

These are proposed engineering improvements; **no benefit below is an observed result**.

### 1. Shared, Versioned Request Certificates

**Invariant:** every supported minting witness satisfies the entire condition and an evidence-compatible issuer schema. **Counterexample:** the branch/environment conjunction above, plus a post-rollout immutable subject tested against a legacy-only domain. **Acceptance:** exhaustive short-string comparison with an independent interpreter; legacy/immutable/custom-template fixtures; zero accepted invalid witnesses. **Benefit metric:** false-witness rate. **Risk/dependency:** schema evidence, Unicode/operator semantics and product explosion. Full SMT is an alternative, not a reason to weaken timeout handling. **Novelty:** shared-context solving is established by Zelkova; evidence-selected GitHub schemas are an unevaluated integration. [16][12]

### 2. Completion-Relative Uncertainty Certificates

**Invariant:** for every enumerated completion, `Must` is contained in its reach set, which is contained in `May`. **Counterexample:** adding an omitted grant opens access; adding an omitted explicit Deny closes it. **Acceptance:** exhaustively enumerate small policy worlds, including correlated Allow/Deny and inconsistent evidence; zero bound violations. **Benefit metric:** unsound categorical decisions, not fewer warnings. **Risk/dependency:** completeness assumptions and abstraction precision. Closed-world analysis is simpler but must be labeled accordingly. **Novelty:** abstract interpretation is established; the proposed evidence taxonomy needs evaluation. [25]

### 3. Credential-Version Containment Replay

**Invariant:** removing a minting edge never deletes independently surviving possession or authority; every claimed durable rotation excludes all modeled reread/reissue routes. **Counterexample:** `S0` reads `K1` after rotation, or `S1` is issued after the cutoff. **Acceptance:** exhaustive bounded schedules with a separate concrete simulator, cycles, alternative roots and uncertain activation; zero false-contained cases. **Benefit metric:** invalid plans rejected. **Risk/dependency:** time bounds and credential inventory; a static cut is cheaper but insufficient. **Novelty:** attack hardening already exists; this evidence-conditioned temporal combination is a hypothesis. [11]

### 4. Dependency-Specific Diff Certificates

**Invariant:** "resolved under this snapshot" requires sufficient current coverage of the relationship's positive, negative and inventory dependencies. **Counterexample:** one trust file truncates while family-wide parse success improves. **Acceptance:** delete/truncate/corrupt each dependency; scope loss must yield "not observed" or "indeterminate," never resolved. Test unrelated-source damage separately. **Benefit metric:** false resolutions under induced parse loss. **Risk/dependency:** accurate dependency read-sets and exhaustive-inventory receipts; family ranks are only diagnostics. **Novelty:** a proposed safety contract, not an established novel algorithm.

### 5. Independently Checkable Local Incident Packages

**Invariant:** canonical facts and decisions replay deterministically without scanned code, credential values or network access. **Counterexample:** changed policy bytes or omitted assumptions leave the same advertised certificate. **Acceptance:** tamper tests, clean-machine replay, permuted file order, different hash seeds and secret-canary searches across outputs/logs. **Benefit metric:** replay divergence and explanation reconstruction failures. **Risk/dependency:** checker trust, redaction and omitted evidence. A signed log alone is weaker. **Novelty:** Appel/Felten's proof-carrying authentication and in-toto predate this proposal; a package is "proof-carrying" only when it contains a checkable derivation, not merely hashes. [30][29]


## 6. Build Independent Labels Before Comparing Tools

**Proposed held-out benchmark:** 80 relationships across at least 20 repository clusters, balanced across supported access, refuted access, indeterminate evidence and temporal containment. Freeze repository/template clusters before development; keep forks and reused workflow copies in the same split. Two reviewers independently label from evidence without seeing tool outputs; a third adjudicates. Record applicable policy statements, context witnesses, missing sources and alternative credential paths. Unresolved cases stay indeterminate.

Report per-class precision/recall, abstention, bound violations and false containment, with repository-cluster bootstrap intervals. Small samples imply wide uncertainty; report class counts and disagreement rather than hiding them inside accuracy. Source receipts should bind document digest, parser/schema versions, byte/AST location, coverage, unsupported constructs, truncation and inventory membership. Decision traces bind witnesses, Deny reasoning, assumptions and transition states.

Mutation operators should include operator swaps, literal `*`, incompatible same-key predicates, condition deletion, absent versus unobserved keys, `IfExists`/`Null`, role-versus-session grants, conditional Deny, missing boundary/session/org/key policies, schema changes, cutoff shifts, alternate reissue paths and credential generations. Check the expected relation, not merely changed finding counts.

Scaling experiments independently vary sparse/dense edges, wildcard products, SCC size, alternative paths, YAML aliases/depth/duplicate keys, malformed inputs, output volume and peak RSS. Record cold/warm wall time, states, grounding size, bytes and explicit cap outcomes. Doubling experiments must expose quadratic edge/output workloads rather than conceal them behind repository counts.

Pin comparator commits, dependencies, inputs, settings, budgets and hardware. Quacky compares policy satisfiability/counting, not end-to-end GitHub containment. `iam-simulate` is an optional offline TypeScript oracle only on its supported intersection: its documentation lists session policies as forthcoming and acknowledges overbroad global-key acceptance. Scanner outputs are predictions, never labels. [10][2]

The **2026-10-19** scanner-study revision reports **2,722 workflows / 388 repositories**, but independent manual labeling covers only **54 workflows** and workflow weaknesses, not AWS relationship truth. Use the source table's artifacts for syntax, mutations and scale, then create the relationship labels independently. [15]

**Decision:** publish dataset rights, pins and exclusions alongside results; do not run repository workflows, deployment examples or downloaded scripts.


## Synthesis

Zelkova/Quacky address request-policy semantics; MulVAL/hardening address multistep derivations and intervention choices; proof-carrying authentication/in-toto address checking and authenticated evidence flow. They differ in **mechanism**, **scope** and **assurance**: satisfiability is not temporal containment, graph reachability is not platform-semantic validation, and signed provenance is not collection completeness. [16][22][18][11][30][29]

Temporal IAM is not an untouched topic either: Christophe Parisel's **2026-06-02** preprint studies structural/temporal identity equivalence with graph fibrations and SCCs, but its single-tenant, in-sample validation does not evaluate temporary-credential survival or containment. It is relevant counterevidence to a broad novelty claim, not an independent oracle for this design. [35]

The defensible differentiation hypothesis is narrower: **schema-correct shared witnesses, directional uncertainty, versioned credential replay and parse-safe decisions can reduce false reachability, false containment and false resolution while preserving offline reproducibility**. The proposed gates can falsify that hypothesis. Until those results exist, describe an integrated analytical contract, not validated superiority.
