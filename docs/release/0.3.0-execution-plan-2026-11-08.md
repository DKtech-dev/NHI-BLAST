# NHI-Blast 0.3.0 Focused Release Execution Plan

> **For agentic workers:** Lead executes and reviews each gated task personally, as requested. No subagents, commits, pushes or publishing. Checkbox completion requires actual verification evidence.

**Goal:** Prepare a tested local `0.3.0` release candidate for the existing offline AWS/GitHub Actions product as soon as its mandatory correctness and safety gates pass.

**Architecture:** Preserve the current Python/Pydantic/NetworkX CLI and reporter boundaries. Repair known supported-fragment semantics and evidence/replay contracts in dependency order; keep essential data independent of decorative animation scheduling. Build final artifacts only after coherent source gates, rather than after every small UI change.

**Tech Stack:** Existing Python 3.12+, Pydantic, NetworkX, SafeLoader parsers, pytest/Hypothesis, Ruff, strict mypy, offline HTML and pinned browser/build tooling. No new framework, cloud service, ML model or unnecessary dependency.

**Spec:** [normative requirements](<../SPEC.md>), [operating contract](<../../AGENTS.md>), [publishing assessment](<publishing-status-2026-11-08.md>), [preserved IO/readability evidence](<io-denial-fix-2026-11-07.md>), and the already approved transformation blueprint recovered locally. This is an execution/prioritization refinement of its minimum safe increment, not permission to remove mandatory requirements.

## Release scope and constraints

- Target package/version/tag agreement is `0.3.0` / `v0.3.0`. Current source remains `0.3.0b1` until the final version-consistency task; do not use a version bump as evidence of readiness.
- Preserve scan/rank/explain/export/schema/version, diff/baseline and what-if capabilities. Do not silently drop unsafe cases or rename certainty to hide a defect. Unsupported contexts must remain explicitly Unknown/indeterminate.
- Mandatory P0 semantics, report source/schema/replay integrity and release gates remain on the critical path. Optional P1 new views/integrations and P2 research features are deferred, not deleted from the roadmap.
- Every graph node/edge retains evidence. UNKNOWN edges do not enter R/E/Z. Identified credentials are not credentials proven obtained; no secret values enter facts/logs/artifacts.
- Core runtime is offline and never executes scanned files, expressions, providers or modules. Parsers remain pure path/text consumers with configured structural/byte limits.
- Preserve all existing modifications, assets and MIT/third-party terms. No reset/clean/history rewrite, artificial commit, upload, deployment or publishing.
- Tests first for meaningful repairs; never weaken assertions, lower floors, increase budgets merely for green results, blindly regenerate goldens, or present historical CI as current evidence.
- No independent security audit, live credential inventory, world-best/novelty/accuracy or employment claim. Native/platform/owner checks that cannot run locally are recorded with exact next actions, not marked passed.
- Automatic goal state is paused in the harness. Its objective was updated to this user-requested release target, but user-side resume is required for unattended continuation; Lead continues direct requested work manually meanwhile.

## Approach choice

Use a release-focused minimum safe increment: current product plus required P0 repairs and scoped uncertainty/reporting fixes, followed by current-source validation and owner handoff. A full transformation including every new UI/research capability would unnecessarily extend this release. A cosmetic version bump or publishing while known false-assurance defects remain is rejected. No hard deadline was supplied; earliest verified readiness is the target, not an invented date.

## Review focus

1. Essential numbers/text must remain correct and readable even if decorative frames are delayed or suspended.
2. Boundary/trust Deny ceilings must apply to conditional as well as definite grants; unsupported request domains cannot emit accepted witnesses.
3. Already/may-held credentials and child sessions must not disappear merely because future issuance is disabled.
4. Parse/source coverage loss must not become a resolved finding, baseline pruning or a replayable complete context.
5. Tags/forks/default dispatch/arbitrary refs/version mismatch must not cause privileged publication or an inferred protected environment.

## Cadence and completion

Use focused failing tests and narrow fixes, then one full gate per coherent source freeze. Keep timing/browser/coverage jobs isolated; durable result files must survive interruptions. Do not spend the release on new decorative features, repeated blind full browser runs, repeated downloads/research, or unexplained test changes. User requested soon; no reliable delivery date is available until the known failures/semantic gates are measured. The first accepted R2 increment is the next estimation checkpoint.

The deliverable is a verified local0.3.0 candidate plus a precise owner publication checklist. Native environment access, any authorized commit/push/CI run, repository protection and public publication remain explicit owner actions—not fabricated completion.
